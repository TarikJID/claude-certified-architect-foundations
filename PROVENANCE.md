# How this course was built, and how to check it

This is the technical companion to [`README.md`](README.md). The README is for someone
studying the course. This is for someone asking where it came from and whether to trust it.

Short version: it was generated by a multi-agent pipeline, and **every claim made about it can be
checked from files in this repo.** Nothing below asks you to take anything on trust.

## How it was made

Generated by [**Certification Trainer**](https://github.com/TarikJID/certification-trainer), which
maps a certification's domains, researches each one in parallel, and assembles a sequenced course.

```
domain-mapper       official exam guide ──▶ domains, objectives verbatim, stable bullet IDs
     │ evaluator ──▶ PASS / REWORK
domain-researcher   ×5 in parallel, one per domain — concepts, prerequisites, sources
     │ evaluator ──▶ PASS / REWORK   (routed only to the instance that failed)
course-builder      modules ▸ lessons ▸ quizzes ▸ exercises
     │ evaluator ──▶ PASS / REWORK
   this course
```

An evaluator runs **between every stage**, not once at the end. A bad early output is consumed by
everything downstream, so a single check at the end tells you the course is wrong without telling
you which stage made it wrong — and throws away all the work built on the bad foundation.

## What's in `runs/`

```
runs/claude-certified-architect-foundations/
  sources/       the exam guide, archived exactly as fetched
  domain-map.md  domains, objectives verbatim, and the bullet IDs everything else cites
  dispatch/      the slice of the map each researcher was handed
  research/      one file per domain — concepts, prerequisites, sources
  evaluations/   11 verdict files, one per stage per round
```

Work was committed between stages, so `git log -p runs/` in the source repo reconstructs the whole
run — what changed, when, and in what order.

## Three claims, and how to check each one

### 1. Nothing was dropped

The exam guide enumerates **240 objective bullets** across 30 task statements. Each was given a
stable ID when the guide was mapped, and cited through to the outline's bullet-to-lesson table. The
check is a set comparison in both directions:

```
bullet IDs in domain-map    : 240
bullet IDs cited in outline : 240
in map but not outline      : 0      nothing in the exam is missing from the course
in outline but not map      : 0      nothing in the course was invented
```

**Check it yourself:** the IDs are in
[`runs/.../domain-map.md`](runs/claude-certified-architect-foundations/domain-map.md) and in the
bullet-to-lesson table at the end of [`course-outline.md`](course-outline.md). Two lists, one
`comm`.

### 2. Every claim traces to a source

Concepts carry the source they came from, and those citations were checked by fetching the pages
and searching them — not by trusting that a URL looked official.

No concept in this course is marked `UNSOURCED`. The pipeline has an escape hatch for concepts that
cannot be sourced after genuine search; on this run it never fired.

**Check it yourself:** pick any concept in
[`runs/.../research/`](runs/claude-certified-architect-foundations/research), open its `Source:`
URL, and search the page.

### 3. The checking is itself on the record

[`runs/.../evaluations/`](runs/claude-certified-architect-foundations/evaluations) holds eleven
verdict files — one per stage per round. Each lists **every** checklist item with an evidence
column, including the ones that passed, plus a separate `Not checked` section naming what was *not*
verified.

Recording passes matters: a file listing only failures is no evidence the rest was ever examined.

**Three rounds came back REWORK**, all for the same reason — citation faithfulness. Real, official,
on-topic pages carrying claims that were not actually on them.

Worth reading in full:
[`domain-researcher-tool-design-mcp-integration-round-1.md`](runs/claude-certified-architect-foundations/evaluations/domain-researcher-tool-design-mcp-integration-round-1.md)
catches a fabricated quote and a fabricated statistic attributed to a real Anthropic page. The
round-2 file shows the corrected version, quoting what the page actually says.

## Two things the pipeline does not check

**Teaching quality.** Coverage and citation accuracy are both verified. Whether a lesson *teaches
well* is a judgement no automated check here makes, and none of the numbers above speak to it.

**Whether the exam guide is still current.** The archived copy in `runs/.../sources/` is what the
course was built from. Comparing it against the live guide is a manual job.

## Known discrepancies

**One path in one verdict file no longer resolves.** The `course-builder` verdict records its output
as `courses/claude-certified-architect-foundations/`, which is where the pipeline wrote it.
Publishing this as a standalone repo moved the modules to the root.

That file was **not** edited to match. An audit trail you tidy up afterwards is not an audit trail —
it records what was checked at the time it was checked, and a discrepancy is better explained than
quietly corrected.

**`course-outline.md` is written in the pipeline's vocabulary** — task statements, bullet IDs,
section numbers like 1.1–5.6. That is coverage bookkeeping, and it is what makes claim 1 checkable.
It is not how a learner should have to think about the material, which is why the README does not
use it.
